## Task 1: Core Implementation & Architecture

### Опис завдання
В рамках **Task 1** було розроблено модульну систему автентифікації та управління користувачами на Python. Реалізація забезпечує безпечне збереження паролів, контроль доступу на основі ролей, обмеження активності сесій за таймаутом та журналювання дій у системі аудиту.

---

### Архітектура та структури даних

Система складається з п'яти основних компонентів:

1. **Клас `User` (Базовий користувач)**
   * **Валідація Email:** Використовує `@property` та `@email.setter` із регулярним виразом `EMAIL_REGEX` для перевірки коректності email перед збереженням[cite: 5].
   * **Безпека паролів:** Не зберігає паролі у відкритому вигляді. Використовує генерацію 16-байтової солі (`os.urandom`) та хешування за алгоритмом **PBKDF2-HMAC-SHA256** (`100,000` ітерацій).
   * **Перевірка:** Метод `check_password()` порівнює хеші за допомогою безпечного до криптоаналізу за часом методу `hmac.compare_digest`.

2. **Клас `Admin` (Спадкоємець `User`)**
   * Розширює базовий клас `User` можливістю керування дозволами (permissions).
   * Містить методи `grant_permission()`, `revoke_permission()` та `has_permission()` для роботи з множиною рольових прав `permissions`.

3. **Клас `Session` (Сесія користувача)**
   * Фіксує IP-адресу, час входу (`login_time`) та час останньої активності (`last_activity`) у форматі UTC.
   * Метод `touch()` оновлює `last_activity` при кожній дії.
   * Метод `is_active(timeout_sec)` перевіряє, чи не перевищено ліміт неактивності (за замовчуванням `900` секунд / 15 хвилин).

4. **Класи `AuditRecord` та `AuditLog` (Журнал аудиту)**
   * `AuditRecord` — дата-клас (`dataclass`) для зберігання структурованого запису про подію (`timestamp`, `username`, `action`).
   * `AuditLog` — веде хронологічний список подій (`self.logs`), підтримує додавання записів через `add_log()` та їх форматований вивід через `show_all()`.

5. **Клас `UserAccount` (Оркестратор системи)**
   * Об'єднує користувача (`User`/`Admin`), сесію (`Session`) та журнал аудиту (`AuditLog`).
   * **Управління входом:** Метод `login()` перевіряє пароль, відкриває сесію та реєструє успішні/невдалі спроби в `AuditLog`.
   * **Магічні методи (`__getitem__`, `__setitem__`):** Забезпечують суворий контроль доступу до атрибутів через словник `ALLOWED_KEYS`. Дозволяють безпечно читати та змінювати лише визначені поля з перевіркою типів даних.

## Task 2: Детектор цілісності файлів та каталогів (File Integrity Monitor — FIM)
Утиліта для автоматизованого моніторингу та виявлення несанкціонованих змін у критичних директоріях системи.

---

###  Функціонал
* **Рекурсивне сканування:** Обхід указаної директорії за допомогою модуля `pathlib.Path`.
* **Хешування та метадані:** Обчислення SHA-256 хеш-сум та збереження структури файлів (шлях, хеш, розмір, час модифікації) за допомогою `@dataclass`.
* **Режим `generate`:** Створення або оновлення еталонного контрольного файла `baseline.json`.
* **Режим `check`:** Порівняння поточного стану системи з еталоном, виявлення модифікованих, нових та видалених файлів.
* **Логування:** Фіксація аномалій у файл логів `fim.log` через `logging.warning`.

---

### Інструкція із запуску (CLI)

Запуск здійснюється через термінал із кореневої директорії проєкту `cybersecurity-python-labs`.

#### 1. Генерація еталонного стану (Baseline)
Створює еталонний файл `baseline.json` на основі поточного вмісту монітореної директорії:
```bash
python -m labs.lab02.main generate
```

#### 2. Перевірка цілісності файлів (Check)
Порівнює поточний стан файлів у монітореній директорії з еталонним файлом `baseline.json` та виявляє модифіковані, нові або видалені файли:
```bash
python -m labs.lab02.main check
```
